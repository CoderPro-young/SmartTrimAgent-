# V5.0 —— 粗剪内核与媒体化前端

> 2026-09-24。对应 roadmap `dirty-work-automation` 的 T10 / T12 / T16 / T18 / T19 与 V4 Phase 4 的 `auto_select` 宏。
>
> 一句话：给「从大量素材里筛出能用的，剪掉没用的」这个定位补上**确定性信号 + 批量筛选宏**，
> 并把前端从「流水线检视器」改造成「素材/成果可视化工具」。

## 0. 背景与定位

两大产品定位（与 roadmap 开篇一致）：

1. **粗剪**：自然语言在大批量素材中初筛——筛指定场景、剪掉静音/黑屏废段；
2. **新手简单剪辑**：一句话出片，不看 JSON、不懂时间码也能用。

V4 之后管线骨架（计划→编译→回验）与感知层（analyze_media 镜头级索引）已就绪，
但两条定位各卡一步：

- 粗剪缺**确定性信号**（静音检测 T10 一直未做）与**批量筛选**
  （模型手抄多区间 trim 必漏，文档自认的一号风险）；
- 新手面对的仍是 JSON 原文 + 纯文字素材列表。

参考对象：**LosslessCut**（源码研读，`D:\lossless-cut`）。它的「把剪辑前的杂活从分钟缩短到秒」
来自一套与模型无关的机械组合：确定性 ffmpeg 信号（silencedetect/blackdetect/场景切分）
→ 区间→片段转换（含补集反转）→ 缩略图/波形可视化。这与本项目「LLM 管意图、编译器管正确性」
的哲学同构，V5 直接吸收其实现模式：

| LosslessCut 做法 | V5 吸收点 |
|---|---|
| `silence_end + silence_duration` 反推区间；末尾静音用总时长补闭合 | `signal_detection.parse_silencedetect` 同款解析 |
| 「剪掉静音」= 静音区间补集（invert segments） | `kept_intervals` 补集 + keep_padding 收缩 + min_keep 过滤 |
| `-ss` 放 `-i` 前快速单帧抽帧，懒加载 | `/thumb` 路由同款 seek；镜头卡直接用已落盘的代表帧 |
| 直接播原文件 + Range | 镜头区间回放：`/input` + `timeupdate` 钳制，无需切片 |

## 1. 粗剪信号内核（后端）

### 1.1 `video_editing/signal_detection.py`（T10 扩充版）

- `detect_silences(src, offset, limit, noise_db, min_silence)`：
  `ffmpeg -map 0:a:0 -af silencedetect=noise=-35dB:d=0.4 -f null -`，
  stderr 正则解析；`-ss` 前置（时间戳归零后加回 offset）；末尾静音补闭合。
  默认阈值面向口播（-35dB / 0.4s），参数计划里可调。
- `detect_blacks(src, …)`：`blackdetect`，镜头盖误录/片头尾黑屏。
- `kept_intervals(removed, lo, hi, pad, min_keep)`：补集反转 + 内边界 pad 收缩
  （不吃词头词尾）+ 碎片段过滤（<0.3s 无意义）。
- `detect_av`：单次解码同时跑两个滤镜（建卡片省一遍解码）。

### 1.2 信号进内容卡片（schema v2）

- `analyze_media` 新建卡片带 `signals: {audio: {silences, silence_ratio}, video: {blacks}}`；
- **旧 v1 卡就地升级**：命中缓存且版本 <2 时只补跑信号检测（不重跑 VLM，零 token），
  升级后落回 sidecar；
- 卡片镜头带 `frame` 字段（代表帧文件名），前端经 `/probe-frame/<name>` 白名单路由取图。

### 1.3 `cut_silence` / `cut_black`（T12）

计划 clip 级编译期展开参数（不是 effects skill——它改变片段结构）：

```json
{"cut_silence": {"noise_db": -35, "min_silence": 0.4, "keep_padding": 0.15, "min_keep": 0.3}}
```

- `plan_schema`：字段白名单 + 范围校验 + 仅 video；Preflight 增 `cut_no_audio`（无音轨问用户）；
- `plan_compiler._expand_cuts`（校验后、`_derive` 前）：
  - 编译期实时跑检测（确定性，不依赖缓存卡），范围锚定 `[trim_start, trim_end]`；
  - 保留区间 = 废段补集（1.1）；一个 clip → N 个子 clip（继承 effects/probe）；
  - **转场落在首个子段条目**，子段之间硬切；overlay 按源时间落点重指到子段并换算 offset；
  - 展开可能产生比转场还短的子段 → `_check_transition_fit` 提前拦下（错误可回传重试）；
  - 展开后进入现有 `_derive`，时间轴数学 / dry-run / 执行 / 回验零特判。

### 1.4 `select` 批量筛选宏（V4 Phase 4 的 auto_select 落地）

LLM 只写筛选意图，编译器从内容卡片**确定性地**生成 clips——结构性杜绝手抄 trim 漏抄：

```json
{"select": {
  "sources": ["INPUT/a.mp4"],
  "where": {"scene_any": ["聚会"], "person_count_min": 2,
            "quality_in": ["good","ok"], "max_silence_ratio": 0.6,
            "min_duration": 1.5},
  "budget_seconds": 30, "order": "as_listed"}}
```

- 与 `clips`/`timeline`/`overlays` 互斥（BGM 仍可用）；
- 条件纯函数（`shot_select.py`，零 IO 可测）：文本宽松匹配（子串双向 + tags），
  预算贪心装填（放不下的跳过继续试更短的），order 支持 `best_first`（画质→时长）；
- 缺卡返回「请先 analyze_media」错误（模型补分析后重提）；无命中建议改走 ask_user；
- 卡片任何标签维度都是条件——用户需求多样化时**不需要新增能力，只需要新的条件组合**。

### 1.5 上传即索引

上传成功 / 刷新素材列表时，服务端后台线程跑 `analyze_media`（等待 RUN_LOCK、静默钩子、
失败 5 分钟退避）；`/api/inputs` 每素材带 `analysis_state: analyzing|ready|failed|unsupported`。
用户开口时卡片多半已就绪，agent 少一步等待。

## 2. 前端：零构建模块化 + 媒体化

### 2.1 模块拆分（决策：零构建原生 JS ES modules，不引框架）

`web/index.html` 瘦身为骨架 + `<script type="module">`；`web/static/js/`：

```
util.js(工具) api.js(NDJSON流) chat.js(对话) materials.js(素材库/上传/有界预览)
shots.js(镜头库/筛选) pipeline.js(参数卡/数学/命令/日志) timeline.js(只读胶片条)
result.js(成品/审阅报告) templates.js(任务模板) app.js(胶水/事件分发)
```

`server.py` 新增 `/static/` 路由（mime + no-cache），保持纯标准库零依赖哲学。

### 2.2 布局：右栏三标签

- **素材库**（默认）：素材列表（**缩略图** + 索引状态徽章）+ 有界预览 +
  **镜头库**（跨素材聚合、缩略图卡、按 有人/无人/画质/场景 纯前端筛选、
  点击区间回放）；
- **成品**：播放器 + **审阅报告卡**（T18）+ **只读时间线胶片条**（片段缩略格宽∝时长、
  转场标记、点击回看源片段；只读不拖拽，Scope Guard「不做 GUI 轨道编辑器」维持）；
- **流水线**（高级）：**参数卡片**（T16，trim 可改、效果 chip 可删、片段可删/排序、
  转场/输出可调，JSON 折叠进「高级」）+ 数学换算 + 命令 + 日志 + 历史产物。

### 2.3 服务端配套

- `GET /thumb/<name>?t=&h=`：`-ss` 前置快速抽帧，`TMP/thumbs/` 缓存（键含 stat）；
- `GET /probe-frame/<f>`：代表帧白名单路由（`[0-9a-f]{12}_\d{3}.jpg`）；
- `POST /api/replan`：跳过 LLM，校验→Preflight→编译→执行→回验，复用 NDJSON 事件流
  （新增 `exec_plan` 事件：编译后**展开的**可执行计划——参数卡编辑的数据源）；
- `POST /api/cancel` + `ffmpeg_exec.kill_all()` + 各阶段检查点（`plan_compiler.Cancelled`）；
- `done` 事件带 `report`（clips/时长/剪除明细/筛选命中/效果/转场/BGM）。

## 3. 验证

- 离线单测（全 mock）：`tests/test_roughcut.py` 26 项（解析/区间数学/卡片信号与升级/
  select 过滤预算/schema 互斥与校验/展开重映射/端到端编译）+ V4 回归 19 项；
- 端到端实测（合成素材 2s 音 + 2s 静音 × 2 + ffmpeg 6.1.1）：
  - 信号精确命中 `[[2,4],[6,8]]`，silence_ratio 0.4；
  - `cut_silence` 出片 5.62s（预期 5.6s）回验一致，报告「剪除 4.0s / 2 段」；
  - `select` 预算 12s 选中 10s 镜头出片；预算 6s 给出「单个最短 10s 装不进预算」精确错误；
  - v1 旧卡自动升级 v2（只补信号，VLM 零调用）；
  - `/thumb` `/probe-frame` `/static` 200，路径穿越 404；空转 cancel 正确 409。

## 4. 边界与不做

- **无筛选确认环节**：按用户决策直接出片（审阅报告事后透明，多轮语言修改兜底）；
- ASR/字幕（T14）：二期（剪口播「嗯啊」需转写信号）；
- GUI 轨道编辑器 / 拖拽剪辑：维持 Scope Guard 不做；
- smart-cut 流复制：现有 concat copy 快速路径已覆盖同编码场景。

## 5. 后续自然延伸

- T13 `auto_xfade`（场景切点自动转场）：信号已齐，只差编译器宏；
- select 支持 `at_time_range`（限定素材时间段内筛选）与镜头合并（相邻同场景）；
- 审阅报告细化（打码覆盖率/黑帧残留断言）；T17 多规格 variants。
