# V7.9 TransNetV2 过碎复核（镜头切分质量升级）

> 2026-10-01。需求来源：对比 FireRed-OpenStoryline（小红书 FireRedTeam
> 开源）后发现其镜头切分不用 ffmpeg 启发式，而是接了 **TransNetV2**
> （专用镜头边界检测网络）。本项目借鉴其做法，以「复核」而非「替换」的
> 方式引入：治的就是我们踩过的频闪/快速甩镜误切老毛病。

## 背景与动机

现行切分（V4 感知层）是 ffmpeg `select=gt(scene,0.3)` 帧差启发式。已知
弱点：频闪/快速甩镜会把 scene 分数间歇性顶过阈值，把一段连续镜头误切成
0.1s 级碎片（实测：10.1s 餐厅素材切成 13 段、12 段不足 0.4s）。现行补救
是「平均粒度 < 1.5s 判误切 → 升阈值 0.45/0.6 重试 → 仍碎取最粗」——升
阈值靠「真实硬切的 scene 分数远高于频闪尖峰」这一经验，每级都要整段
重新解码，且本质仍是启发式打补丁。

OpenStoryline 的做法（`split_shots.py`）：ffmpeg 管道解码到 48×27 RGB
@25fps → TransNetV2 逐帧预测转场概率 → 阈值 0.5 得边界 → min/max 时长
护栏（<1s 并段、>max 均匀强切）。模型在学界与工业界（腾讯混元管线、
TEMPLE 论文等）均被验证比 PySceneDetect 类启发式更准，且输入分辨率极低，
CPU 可跑（实测 30s 素材推理约 8s）。

## 方案：融合而非替换

```
ffmpeg scene 0.3 首轮切分
  ├─ 粒度达标（平均 ≥ 1.5s）→ 直接用（快路径，零新增开销）      how=scene
  ├─ 判过碎 → TransNetV2 重切一遍
  │    ├─ 模型边界更粗（含整段一镜）或粒度达标 → 采纳，        how=transnet
  │    │   跳过升阈值（省 1~2 遍全片解码）
  │    └─ 模型比启发式还碎 / 复核失败 / 未装依赖 → 走原阶梯
  └─ 升阈值 0.45 → 0.6 重试（原行为不变）                how=scene_rescued
```

关键决策：

- **只在过碎时请模型**：干净素材的行为、耗时与从前完全一致；模型只在
  启发式已被判不可信的素材上出手续费。
- **模型更粗即采纳**：TransNetV2 见过大量真实转场，其边界比「升阈值
  取最粗」更接近真值；真·快剪素材（模型也说碎）不会被升阈值误并——
  这正是升阈值阶梯的盲区。
- **可选依赖、优雅降级**：`transnetv2_pytorch`（MIT，pip 包自带权重）
  不装也能跑，`detect` 任何失败返回 None，回退阶梯与 V7.8 逐字节一致。
  复核不可用**不算降级**（老路径本身就是完整方案），不进卡片
  `degradations`。

## 实现

- `video_editing/transnet.py`（新增）：解码（`fps=25,scale=48:27` rawvideo
  管道，与 OpenStoryline `read_video_frames_as_rgb24` 同参数）→ 模型
  `predict_raw` → `predictions_to_scenes_with_data` → `scenes_to_boundaries`
  （与 `parse_showinfo` 同口径：滤 ≈0、四舍五入 3 位）。模型 lru_cache
  常驻；全程不抛异常。
- `video_editing/ffmpeg_exec.py`：新增 `run_binary`（二进制 stdout 捕获，
  供 rawvideo 管道；进程同样进 `_PROCS`，「取消任务」对它生效）。
- `video_editing/content_analysis.py`：`_detect_boundaries` 增 `transnet_fn`
  注入点与复核分支；`analyze_media` 卡片新增 **`segmentation`** 字段
  （`scene` / `transnet` / `scene_rescued` / `uniform` / `image`），旧缓存
  卡片缺该字段由 `.get` 消费者兜底。后续护栏（<0.5s 并段、12s 等分、
  帧预算抽样）对模型边界原样生效。

## 配置

```
pip install transnetv2_pytorch==1.0.5   # 可选；包内自带权重（MIT）
TRANSNET_RESCUE=0        # 关闭复核（默认开）
TRANSNET_DEVICE=cpu      # 推理设备（默认 cpu，确定性优先）
TRANSNET_WEIGHTS=...     # 自定义 .pth 覆盖权重（如 OpenStoryline 仓库副本）
```

未安装 torch / 包 / 权重读取失败 → 复核自动缺席，日志无噪音。

## 实测

合成 30s 素材（红/蓝/绿/黄/白 各 6s，硬切于 6/12/18/24s）：

- `transnet.detect` → **[6.0, 12.0, 18.0, 24.0]**，4 刀全中（CPU 7.7s）。
- ffmpeg scene 0.3 → `[6.0, 12.0, 18.0]`，**漏掉 yellow→white 一刀**
  （亮度差太小，帧差分数不过线）——启发式漏切的直接证据。
- 复核路径单测（`tests/test_v79_transnet_rescue.py`，全 mock 离线）：
  11/11 通过，覆盖采纳/回退/零调用/更碎忽略/整段一镜/开关/卡片字段。

## 与 OpenStoryline 的差异

| | OpenStoryline | 本项目 V7.9 |
|---|---|---|
| 定位 | 主切分器（每素材必跑） | 过碎复核（启发式失败才跑） |
| 依赖 | 必装（torch + 权重） | 可选（不装行为不变） |
| 产出 | 物理切片文件（-c copy） | 时间边界进内容卡片（零拷贝） |
| 长镜头/碎段护栏 | 自带（1s~max 强切） | 复用本项目护栏（0.5s 并段 / 12s 等分 / 帧预算） |

## V7.10 升级：TransNetV2 升为主切分器（B 方案）

> 2026-10-01。复核形态落地后的复盘：①依赖未装时复核是静默死路（本机实测
> torch 缺失，模型一次未跑过）；②「过碎才触发」存在盲区——**渐变转场漏切
> （欠切）不会让粒度变碎**，模型永远不会被请来救漏切，而漏切正是文案
> 「一句描述两个场景」的病根之一。对比 FireRed 后决定抄全套：模型升为
> 主切分器。

新流程：

```
TransNetV2 主切分（所有视频默认）
  ├─ 成功 → 直接采纳（护栏在 build_shots：<0.5s 并段、超长均匀强切）
  └─ 失败/未装依赖 → ffmpeg 启发式阶梯（原行为整体保留，
      含过碎时的模型复核——但模型刚失败过则不再重复调用）
```

开关（.env.example 有完整说明）：

- `TRANSNET_PRIMARY=0` 回到 V7.9 过碎复核旧形态；
- `TRANSNET_RESCUE=0` 整体不接模型，纯 ffmpeg（行为同 V7.8）；
- 卡片 `segmentation` 字段：`transnet`（主切分采纳，与复核采纳同值）/
  `scene` / `scene_rescued` / `uniform`。

代价：每条素材分析多一次 48×27@25fps 解码 + CPU 推理（实测 30s 素材约
8s），sidecar 缓存后一次性。
