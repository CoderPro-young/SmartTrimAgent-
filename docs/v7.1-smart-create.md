# V7.1 —— 双模式前端 + 智能创作（smart_create）

> 2026-09-28。产品形态收敛为**双模式**：粗剪模式（V5/V6 的减法漏斗）与
> 智能创作（FireRed 式一键成片）。TTS 配音按决策暂缓——智能创作 v1 的成片
> 形态 = **画面 + LLM 文案字幕（烧录）+ fade 转场 + 可选 BGM**，无旁白音频。

## 1. 前端双模式

- 输入区顶部新增模式切换（✂️ 粗剪模式 / ✨ 智能创作），选择存 localStorage；
- 两套任务模板与占位文案随模式切换；模式只影响前端引导，任务文本自然携带
  意图，服务端协议零改动。

## 2. smart_create workflow 宏（第三个内置工作流）

分工延续「LLM 出意图、编译器保正确」：**文案是 LLM 的创意职责**（读镜头卡
后写贴合画面的短句），**排版烧录是编译器的确定性职责**：

```
{"workflow": {"name": "smart_create",
              "captions": ["山野的风不需要滤镜", "日落是白昼温柔的谢幕"],
              "budget_seconds": 25, "keyword": "日落"}}
```

- 展开链：粗筛丢废料 → 画质选材（可选 keyword 跨字段 OR）→ 预算贪心 →
  fade 转场 → clips/timeline（同 one_click_reel 的编排层）；
- **`_apply_captions`（编译器新阶段，_derive 之后）**：文案行均分总时长成
  时间槽（槽间留 8% 间隔），逐行生成 text overlay（bottom / 44px / 白色），
  at_clip 挂在覆盖起始时间的片段上；字幕跨片段边界无碍——drawtext 的
  enable 是绝对时间轴，渲染在拼接/转场后的主画面上；
- captions 由 `_captions` 暂存键从 workflow 展开传递到铺字幕阶段（此时才有
  总时长 D），消费后从计划中移除（不出现在 exec_plan 事件里）。

## 3. 修复（本轮实测发现）

- **select/workflow 宏生成的 clips 不带 probe**：无音轨素材归一化时不会补
  anullsrc，渲染段 `[i:a]` 引用即失败（智能创作轮真实触发）。修复：归一化时
  probe 缺失则现场 ffprobe 判音轨；有声轨与否（amap）纳入内容寻址缓存键。

## 4. 验证

- 单测 13 项（smart_create 无 captions 报错 / 展开带 _captions / 编译铺字幕
  时序与挂载片段 / captions 校验）+ 全量回归；
- 端到端宏路径：3 句文案 17.24s 出片回验一致；
- 端到端 LLM 路径：「做成带文案的成片」→ 模型读 6 张卡、自行写 5 句文案、
  提交宏 → 23.1s 回验一致；抽帧经 VLM 复核确认字幕已烧录且内容正确
  （「风穿过林间，光落在肩上」）。
