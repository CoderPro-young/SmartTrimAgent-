# 人脸马赛克能力 —— 技术方案（v3.0）

> 目标：用户说「给所有人脸打上马赛克」，最终输出视频中人脸被打码。
> 本文承接 [v2.0-multi-material-editing.md](./v2.0-multi-material-editing.md) 的架构，
> 讨论如何把人脸检测/打码作为一个**新的 agent 能力**接进现有「LLM 出计划 → 编译器出命令」链路。

---

## 1. 需求拆解

一句自然语言背后是四个子问题：

| 子问题 | 说明 | 难点 |
|---|---|---|
| ① 意图识别 | 从「打马赛克」识别出要执行「人脸检测 + 打码」 | LLM 侧，靠 system prompt 声明能力即可 |
| ② 人脸检测 | 找到每一帧里所有人脸的 bbox | 需要开源检测模型 |
| ③ 打码渲染 | 对 bbox 区域做像素化/模糊 | OpenCV 即可，纯程序 |
| ④ 时间一致性 | 视频帧间不闪烁、不丢脸 | 跟踪/平滑，工程难点 |

结论：**①由 LLM 负责（新增一个 effect 声明），②③④由程序负责（新增一个 Python 模块）。**
不改变「LLM 出意图、编译器出工程」的基本分工。

---

## 2. 现状与接入点

现有能力通过三个通用扩展点接入（见 v2.0 详细设计 §12），人脸马赛克天然落在第一个：

```
clip.effects: [ {"name": "hflip"}, {"name": "eq", "args": {...}} ]   ← 现有
clip.effects: [ {"name": "face_mosaic", "args": {...}} ]            ← 新增
```

但要注意：`hflip`/`eq` 是**纯 ffmpeg 滤镜**，能直接拼进 `-vf`；`face_mosaic` 不一样——
ffmpeg **没有内置的人脸检测器**（虽有 `dnn_processing`/`delogo` 但不支持检测+跟踪），
必须由一个外部「检测+打码」程序预处理出中间视频，再进入现有的归一化/渲染流程。

因此接入方式不是加一条滤镜，而是**在归一化阶段前插入一个独立的"检测打码"命令**。

---

## 3. 人脸检测模型选型

调研结论（2026-09，基于 WIDER Face 基准与社区评测）：

| 模型 | 引擎 / 许可 | 模型大小 | WIDER-Face Hard | 速度(CPU) | 商用 | 结论 |
|---|---|---|---|---|---|---|
| **YuNet** | OpenCV / **MIT** | ~230 KB (75K 参数) | ~81% | ~1.6 ms/帧 | ✅ 安全 | **默认首选** |
| SCRFD | InsightFace / 代码 MIT，**权重 research-only** | 0.5~34GF | ~87% | 快 | ⚠️ 需授权 | 精度更高，商用要谈 |
| RetinaFace | InsightFace / **权重非商用** | 1.7~105 MB | ~91.4% | 较慢 | ⚠️ 需授权 | 旧 SOTA，偏重 |
| BlazeFace | MediaPipe / Apache-2.0 | ~224 KB | 中 | ~2.2 ms | ✅ 安全 | 短距离/自拍场景 |
| MTCNN | 老方案 | ~2 MB | 中 | 慢 | ✅ | 小脸弱，不推荐 |
| Haar Cascade | OpenCV 内置 | 小 | 低 | 快 | ✅ | 精度不够，仅兜底 |
| YOLO-Face | 第三方(Ultralytics) | ~45 MB | 高 | 快(GPU) | ⚠️ **AGPL 传染** | 闭源产品慎用 |

**选型结论：**

- **第一版用 YuNet**（`face_detection_yunet_2023mar.onnx`，OpenCV `FaceDetectorYN` API）。
  理由：MIT 许可商用零风险、CPU 上 1.6ms 级实时、自带 5 点关键点、无需 GPU、
  模型仅 230KB 可随仓库分发。这是 LearnOpenCV 官方 FaceBlurPixelate 教程同款方案。
- **精度不够再上 SCRFD**（InsightFace）：检测小脸/密集人群更强，但**权重仅限非商用研究**，
  商用需向 InsightFace 单独授权——这是产品化前必须确认的 license 风险。
- 识别（区分"给谁打码"）是另一条线，见 §7 分期，第一版不做。

## 4. 打码算法

对 bbox 区域做视觉遮蔽，两种模式（OpenCV 实现，均无额外依赖）：

1. **像素化（mosaic，默认）**：把 bbox 区域 `resize` 缩小再 `INTER_NEAREST` 放大，
   块大小即"马赛克颗粒度"（默认 20px）。匿名性最强，是用户语义里的"马赛克"。
2. **高斯模糊（blur）**：`GaussianBlur`，核大小随脸宽自适应（如 `kernel = max(15, w//10)|1`）。
   观感更自然，适合"打码但保留轮廓"的场景。

bbox 需外扩 padding（如 20%），避免脸移动时边缘漏码。

---

## 5. 关键难点：帧间闪烁（时间一致性）

单帧检测结果在帧间抖动，直接逐帧打码会产生"马赛克闪烁/漏脸"。治理分三档：

| 档位 | 策略 | 复杂度 | 效果 |
|---|---|---|---|
| L1 | 检测失败时**沿用上一帧 bbox**（短时 hold + 渐隐） | 低 | 消除大部分闪烁 |
| L2 | 相邻帧 **IoU 匹配**建立 track，同一 track 内 bbox **指数平滑** | 中 | 顺滑、稳定 |
| L3 | 光流 / ByteTrack 追踪 + 抽帧检测插值 | 高 | 大幅提速 + 稳 |

**第一版做 L1+L2**（纯 NumPy，无需新依赖）：
- 每个 track 保存 bbox、置信度、关键点、`missed` 计数；
- 新帧检测结果与上一帧各 track 做 IoU 匹配（阈值 ~0.3）；
- 匹配上 → 平滑更新；未匹配到新检测 → `missed++`，沿用旧框最多 N 帧（如 8 帧）后丢弃；
- 置信度阈值默认 0.7（低于则判定"未检测到脸"）。

## 6. 架构设计

### 6.1 新增模块 `video_editing/face_mosaic.py`

职责单一：输入视频 → 逐帧检测 + 跟踪平滑 + 打码 → 输出打码后的视频（**保留音频**）。

```python
# 对外主函数
def apply_face_mosaic(
    src: str,                # INPUT/xxx.mp4
    dst: str,                # TMP/xxx_masked.mp4
    mode: str = "mosaic",    # mosaic | blur
    block_size: int = 20,    # mosaic 颗粒度
    score_threshold: float = 0.7,
    model_path: str = "models/face_detection_yunet_2023mar.onnx",
    target: str = "all",     # all | largest（第一个人脸）| index:N
) -> dict:
    """返回 {"ok": bool, "faces_detected": int, "frames": int, "note": str}"""

# 同时提供 CLI，供编译器作为子命令调用
#   python -m video_editing.face_mosaic --input ... --output ... [--mode ...]
```

实现要点：
- `cv2.VideoCapture` 读帧 → `FaceDetectorYN` 检测 → 跟踪平滑 → 打码 → `cv2.VideoWriter` 写帧；
- 视频帧率/分辨率/像素格式与源一致（避免重编码错位）；
- 音频不经过 OpenCV，最后用 ffmpeg `-map` 从源流 copy 回来（或直接用 ffmpeg 提音轨后 `-c:a copy` 合流）。

### 6.2 扩展 plan 语义（`plan_schema.py`）

```python
EFFECTS = {"hflip", "vflip", "transpose", "eq", "face_mosaic"}   # 白名单新增
```

`face_mosaic` 的参数校验（新增分支）：

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `mode` | str | `mosaic` | `mosaic` / `blur` |
| `block_size` | int | 20 | 2~64 |
| `score_threshold` | float | 0.7 | 0.3~0.99 |
| `target` | str | `all` | `all` / `largest` / `index:N` |

### 6.3 扩展编译器（`plan_compiler.py`）

`_effects_to_vf` 目前把 effects 拼成 ffmpeg 滤镜串。改为：**把 effects 拆成两类**——

- 纯滤镜类（hflip/vflip/transpose/eq）→ 仍拼 `-vf`；
- 检测打码类（face_mosaic）→ **生成一条独立的"检测打码"命令**，插在该 clip 归一化命令之前，
  且归一化命令的输入从 `INPUT/xxx.mp4` 换成打码后的 `TMP/xxx_masked.mp4`。

命令形态（`stage="detect"`）：

```
python -m video_editing.face_mosaic
    --input INPUT/sample.mp4 --output TMP/c1_masked.mp4 --mode mosaic --block-size 20
```

这样复用现有的 `execute()` 逐条执行 + `verify()` 回验框架，无需新增执行器。

### 6.4 扩展 Agent（`video_agent.py`）

在 `V2_SYSTEM_PROMPT` 的 plan schema 示例中，给 clip 增加 face_mosaic 用法说明，
让 LLM 知道「人脸打码 = 给对应 clip 加 `{"name": "face_mosaic", "args": {...}}`」。

## 7. 数据流（完整链路）

```
用户："给所有人脸打上马赛克"
   │
   ▼
LLM（video_agent）── ls/probe_media ──► submit_plan
   │        clips[0].effects = [{"name":"face_mosaic","args":{"mode":"mosaic"}}]
   ▼
plan_schema.validate ──► 白名单 + 参数校验（通过）
   ▼
plan_compiler.compile
   ├─ 识别 face_mosaic → 生成 [detect] 命令：python face_mosaic.py …
   ├─ 归一化命令输入改为 TMP/c1_masked.mp4
   └─ 后续 concat/xfade/overlay 流程不变
   ▼
execute：python 检测打码（保留音频）→ ffmpeg 归一化 → ffmpeg 渲染
   ▼
OUTPUT/final.mp4（人脸已打码）
```

## 8. 性能与工程注意点

- **抽帧检测**：720p 视频可每 2~3 帧检测一次、中间帧用 track 插值，CPU 上仍能接近实时。
- **GPU 加速**：后续用 ONNX Runtime CUDA / TensorRT 跑 YuNet 或换 SCRFD，吞吐 3~5 倍。
- **音频保真**：音频全程不重编码，`-c:a copy` 直接搬。
- **模型分发**：YuNet 仅 230KB，放 `models/` 随仓库分发；SCRFD 需显式下载脚本。
- **依赖隔离**：`opencv-python`（含 `opencv-contrib` 不需要，`FaceDetectorYN` 在核心包内）+ `numpy`。
  建议写入 `requirements.txt`，并在 venv 内安装（遵循项目现有隔离约定）。

## 9. 分阶段实施

| 阶段 | 内容 | 交付标准 |
|---|---|---|
| **P0（MVP）** | YuNet 检测 + mosaic/blur 打码 + L1 沿用框平滑 + 音频保留；接入 effect 白名单与编译器 | 输入一句"打码"能产出打码视频 |
| **P1** | L2 IoM 跟踪 + bbox 平滑 + 参数校验补全 + 抽帧优化 + CLI 参数对齐 | 多人脸、运动场景不闪烁 |
| **P2** | SCRFD 高精度切换（评估 license）+ GPU 加速 + 指定目标打码（largest/index） | 复杂场景可用 |
| **P3** | 人脸识别 + 指定人物打码（"只给张三打码"）+ 关键帧手动校正 | 真正的"语义级"打码 |

---

## 10. 风险与边界

- **license**：YuNet(MIT) 安全；SCRFD/RetinaFace 权重 research-only，商用需授权；YOLO 系有 AGPL 传染风险。
- **侧脸/遮挡/超小脸**：YuNet 对小脸、侧脸召回有限，漏检会漏码（L1 兜底可缓解闪烁但不救漏检）。
- **合规**：人脸打码属于隐私保护用途，合法；但本能力不应用于规避内容审核。
- **依赖环境**：需安装 `opencv-python`；未装 ffmpeg 时，检测打码仍可用（OpenCV 独立渲染），
  但合流/归一化仍需 ffmpeg。
