# V8.0 —— 创作流 agent 化：按 WORKFLOW SKILL 逐步执行，产出计划交给下游

> 2026-10-05。动机：宏展开（粗筛→画质选材→确定性装填）的成片效果不如
> FireRed-OpenStoryline（小红书 FireRedTeam 开源）。复盘结论：FireRed 的精髓
> 恰是「**LLM 只做非确定性的筛选/分组/文案，时间线组织与渲染是确定性代码**」
> ——与本项目「LLM 出意图、编译器保正确」完全兼容。V8.0 把创作类任务的
> **判断环节**（选材/分组/文案/选曲）从编译器宏展开移交给 agent 逐步执行，
> agent 产出一份**手写的完整计划**，下游编译链（校验→Preflight→时间轴数学
> →铺字幕→dry-run→渲染→回验→EDL）原样复用，质量门禁零削弱。

## 与 FireRed WORKFLOW SKILL 的对照

FireRed：SKILL.md（markdown 主流程）指导 LLM 逐步调用 MCP 节点工具
（load_media→split_shots→understand_clips→filter_clips→group_clips→
generate_script→select_bgm→plan_timeline→render_video），每个节点内部还有
LLM 调用；plan_timeline/render 是确定性代码。

本项目 V8.0：**agent 就是那个 LLM**，不需要"节点工具内再套 LLM"——判断类
步骤合并为 agent 自己做，只补齐它缺的两个"输入视图"工具：

| FireRed 节点 | 本项目对应 | 形态 |
| --- | --- | --- |
| load_media | `probe_media`（已有） | 工具 |
| split_shots + understand_clips | `analyze_media`（V4 已有） | 工具（内容卡 sidecar 缓存，上传即索引） |
| filter_clips | **`list_shots()`（新）** + agent 判断 | 工具给全量镜头池（无粗筛无预过滤，⚠ 仅标注），筛选规则进提示词 |
| group_clips | agent 判断（规则进提示词） | 无新工具 |
| generate_script | agent 直接写 `_narration` | 计划键（编译器铺轴） |
| select_bgm | **`list_music()`（新）** + agent 选择 | 工具给候选，写入 audio 块 |
| plan_timeline | `_derive` 时间轴数学（已有） | 确定性代码 |
| render_video | 编译器渲染链（已有） | 确定性代码 |

借进提示词的 FireRed 规则（来源 `prompts/tasks/filter_clips|group_clips`）：
镜头 ≤5 不删、保留 >80% 且 ≥5、相似画面留优去重；Hook→Core→Vibe→End
叙事分组、场景聚合禁 A→B→A、单组 2–4 镜 / 3–20s。

## 决策记录

1. **宏保留为兜底**（未采纳彻底移除）：`workflow` 宏注册表不动，提示词里
   降位为「简单批量/参数明确的任务可用」；`/api/replan` 参数卡回改与确定性
   批量场景不受影响。两条路共用同一套下游编译器。
2. **BGM 由 agent 自选**：`list_music()` 给候选（曲库优先 + INPUT/ 纯音频），
   agent 写 audio 块；不想要就不写，**没有自动兜底**——忠实 FireRed 的
   select_bgM 步骤，行为可预测。
3. **取消创作流强制粗筛**（用户拍板「先不做粗筛」）：`_usable_cards` 不再
   调 `culling.judge_material` 判废拦截——agent 路径经 list_shots 看到全量
   镜头池（⚠ 标注 poor/高静音/过短，判断权在模型）；宏路径由镜头级
   quality/静音过滤兜底。**素材库 UI 的手动粗筛报告
   （`/api/cull/report|apply`）不受影响**；speech_clean 的「无音轨跳过」
   保留（那是剪静音的前置条件，不是粗筛）。
4. **agent 手写文案进计划**：`_narration`（旁白制，按叙事组）/
   `_captions`（一镜一句）/`_caption_style`/`_title` 四个键进 PLAN_KEYS
   白名单（编译器消费后移除，exec_plan/replan 不再见到内部键）；与
   `workflow` 宏互斥（防双重来源）。铺轴复用 V7.11 的
   `_apply_narration`（组时间窗内按字数加权、末条吃余数、句可跨剪辑点）。

## 实现

- `video_editing/video_agent.py`：
  - 新工具 `list_shots()`：扫 INPUT/ 已建卡素材，每镜头一行（shot_id/时间
    区间/时长/场景/人数/画质/静音比/desc 截断 40 字）；纯音频跳过；缺卡
    素材列出提示先 analyze_media；⚠ 标注不做拦截。
  - 新工具 `list_music()`：MUSIC/meta.json（title/genre/tags/duration）+
    INPUT/ 纯音频（ffprobe 时长）。
  - 系统提示词新增「Creative workflow (V8)」段：七步流程 + FireRed 筛选/
    分组硬规则 + `_narration` 写法示例；宏文档（render_workflow_doc）降位
    为 DETERMINISTIC FALLBACK。
- `video_editing/plan_schema.py`：`_validate_agent_captions`——四键形状
  校验（组对象白名单 group_id/clip_ids/units、clip_ids 必须引用真实 clip、
  units 非空字符串数组、caption 行数上限分档、样式名 ∈ CAPTION_STYLES）；
  `_narration`×`_captions` 互斥；带 workflow 块时拒绝手写。
- `video_editing/plan_compiler.py`：`_expand_plan` 对手写文案键记
  `expansions["captions"] = {source: "agent", mode, style, title, captions}`，
  弹出 `_title`；铺轴仍走 `_apply_captions/_apply_narration`（零改动）。
- `web/server.py::_build_report`：透传 captions 扩展，title 提升到报告顶层；
  `result.js` 显示「旁白 N 句（agent 按叙事组撰写…）/ 字幕 N 句」。
- `video_editing/workflow.py`：`_usable_cards` 移除判废调用；两个宏展开的
  「全被剔除」报错分支改为「无已建卡素材」；模块头记 V8.0 变更。

## 防线不变（agent 手写计划的风险承接）

- 手抄 trim 越界 / 编造 probe → Preflight `check_material_fit`（over_range/
  probe_mismatch，真实探针为准）；
- 文案键形状错 → schema 校验错误回传重出（≤2 次，错误带节点路径）；
- 幻觉时间戳 → 铺轴只消费 clip_ids（必须真实存在），字幕时间全由编译器算。

## 实测（真实 LLM + VLM，合成双素材 12s+9s）

- **工具序列完全符合设计**：`ls → analyze_media×2 → list_shots → list_music
  → probe_media×2 → submit_plan`——先建卡、再拿全量池、选曲、探测后提交，
  没有跳步，没有用 workflow 宏。
- **计划形态正确**：手写 6 个 clips，trim 与镜头边界逐一相等
  （0-3/3-6/9s 素材的三段 + 0-4/4-8/12s 素材的三段）；叙事组按内容交替
  分组（食物组/出行组），每组 text 原文 + units 断句；`_title` 全片标题；
  audio 块自选曲库曲目。
- **防御闭环有效**：首跑时模型在组里多写了 `text` 字段被 schema 以
  `_narration[0] 含不支持的字段 ['text']` 打回，一次重试即通过——据此把
  `text` 升格为合法可选字段（FireRed raw_text 同位），只写 text 不写 units
  时编译器用标点断句；复跑**零重试**。
- 审阅报告：`captions = {source: "agent", mode: "narration", title: …,
  captions: 6}`，铺轴 6 条字幕 overlay。
