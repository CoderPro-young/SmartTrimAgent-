# V7.2 —— 感知粒度护栏 + 装填来源均衡 + 文案选材后对齐

> 2026-09-29。大版本 V7 上的一次迭代修复：用 4 条微信素材的实测暴露了
> 感知层与选材装填的三个真实缺陷，本轮一并修掉。改动集中在
> `content_analysis.py`（切分护栏）、`shot_select.py`（装填策略）、
> `workflow.py` + `plan_compiler.py`（文案时序）。

## 1. 实测暴露的三个问题

同一批素材（4 条微信视频，40.4s/8.6s/10.1s/69.9s）跑「智能创作·25 秒」：

| 现象 | 证据 | 根因 |
|---|---|---|
| 镜头切分粒度两极化 | 833 被切成 13 段（12 段 <0.4s）；737 整段无切点被等分成 6×11.65s | 频闪/甩镜把 scene 分数间歇顶过 0.3 阈值误切；长镜头走 12s 等分兜底 |
| 成片只有 2 个真场景 + 0.08s 闪帧 | picks = 737×2（11.65s）+ 833 碎片 1.6s + **0.067s** | 全局贪心被单素材长镜头占满预算；候选无最短时长门槛 |
| 文案与画面完全对不上 | 「一家人笑得多甜」铺在无人的草地飞鸟上（person_count=0） | 文案写在选材**之前**（读全量卡写故事线），且铺轴是均分时间槽 |

## 2. 四项修复

### 2.1 切分护栏（content_analysis.py）

- **`_merge_short_shots`**：<0.5s 的碎段并入相邻镜头（开头碎段被后段吸收），
  频闪/甩镜误切不再产出碎片段；`build_shots` 在等分兜底**之前**执行合并。
- **`_detect_boundaries` 过碎重试**：检出边界的平均粒度
  `_avg_shot_span < OVERSEG_AVG(1.5s)` 判为误切，逐级升阈值重试
  （0.3 → 0.45 → 0.6；真实硬切的 scene 分数远高于频闪尖峰，升阈值只滤
  误切不丢真切）；全部仍碎取边界最少的一档，残余碎片交给并段护栏。
  探测失败/整段无切点的兜底行为不变（均匀等分 / 12s 粒度等分）。

### 2.2 装填门槛（workflow.py + shot_select.py）

- 两个一键工作流（one_click_reel / smart_create）的 where 统一加
  `min_duration: 1.5`（`MIN_SHOT_DURATION`）——比这更短的碎片
  （闪帧/频闪段）在候选层直接拒绝，写进 rejected 报告（原因「时长
  X.Xs 短于 1.5s」）。select 宏不受影响（agent 可显式传 min_duration）。
- 预算只减不增：轮转中装不下的镜头直接标拒（以后也装不下），
  同来源更短的后续镜头仍有机会进片——杜绝「靠 0.08s 凑数」。

### 2.3 来源均衡（shot_select.py）

- `best_first` + 有预算时的装填从**全局贪心**改为**跨素材轮转**：
  每条素材轮流贡献镜头，避免单素材的长镜头占满预算把其他来源全部
  挤出。同预算下多素材任务每个来源都出镜；单素材/无预算路径行为不变。

### 2.4 文案选材后对齐（workflow.py + plan_compiler.py）

- **captions 变为可选**：计划不带 captions 不再报错。选材（确定性）
  完成后，`_write_captions` 把**选中的镜头序列**（场景/活动/氛围/人数/
  标签 + 时长，按序）回喂 LLM，一句一镜现写；失败退 `_label_captions`
  标签拼接。三档来源记录在 `report.captions_source`（plan/llm/labels）。
  与 FireRed 流水线同构——generate_script 排在 filter/group 之后。
- **`_apply_captions` 逐片段绑定**：文案行数 == 片段数时第 i 句贴第 i 个
  片段（start_offset 0.05s、时长 = 片段长 − 0.1s，避开 fade 起止）；
  数量不齐（agent 自带且对不上）时退回旧的均分铺轴。

## 3. 行为变化

- 老卡片（sidecar 缓存）不自动重建：min_duration 在候选层照常拦截
  碎段；想让新切分护栏生效需删除 `TMP/probe/` 对应卡片或重新 analyze。
- smart_create 的提示词不再要求 agent 预写文案；`captions` 字段仍合法
  （用户指定文案时用），数量与片段一致时逐段绑定。
- plan 顶层 `_captions` 仍只在展开后由编译器消费，校验白名单不变。

  轮转均衡/同源更短补位/无预算序；文案回喂/逐段绑定/数量不齐回退）

  （假 model 模块直测 JSON 解析/数量不符/异常/非 JSON 四分支）。
  全量 97/97 绿。
- 进程内真实卡片直跑（不经服务）：4 张卡 → 5 片段、3 来源
  （300 10.09s → 860 8.57s → 833×3：2.27/1.87/1.77s），最短 1.767s、
  闪帧 0、captions 5==5 source=llm、rejected_total=19。
- e2e（HTTP，重启用新代码后）：同样 5 片段/3 来源，回验
  ok=True 23.37s（expected 23.37），反问 0/编译错误 0/1 轮出片。
- 抽帧（12s 处）视觉确认：860 公路镜头上烧录第 2 句文案
  「蓝天白云下一条大路」，与画面内容一致——逐片段绑定生效。
