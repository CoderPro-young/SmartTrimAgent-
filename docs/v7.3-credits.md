# V7.3 致谢滚动字幕（subtitle_style: "credits"）

> 2026-09-29。smart_create 新增字幕排版参数 `subtitle_style`，第一种新样式是
> **credits 致谢滚动体**：全部文案合并成一整块逐行居中的白字描边文本，
> 跨全片时长从画面底部匀速滚到顶部（电影片尾致谢的样子，速度随时长自适应）。
> 使用形态：家庭集锦的片尾名单、活动记录的感谢名单、多人旅行的分工致谢。

## 设计

- **排版策略与渲染解耦**：策略收在 `workflow.CAPTION_STYLES` 预设表里
  （合法值 + 字号/行距/描边/贴底比例），渲染层只有两个原语——
  `sequential`（逐条 enable，V7.1 以来的底部字幕）与 `scroll`
  （整块滚动 y 表达式）。**新样式 = 加一行预设 + 补 usage 文案，不动渲染代码。**
- 预设表（现状）：

  | 样式 | mode | 参数 |
  | --- | --- | --- |
  | `bottom`（默认） | sequential | 44px，`bottom_margin_ratio: 0.12`（V7.6） |
  | `credits` | scroll | 40px，行距 14，描边 2，逐行居中 |

- **行数上限分档**：普通逐句字幕一条文案对一个镜头，`CAPTION_LINES_LIMIT=12`
  足够；致谢名单是「分类头 + 名单行」，行数天然多，放宽到
  `CAPTION_LINES_LIMIT_CREDITS=60`（schema 按 style 选档报错）。

## 滚动原语的实现（plan_compiler）

- `overlay.scroll: "up"`：`x = (w-text_w)/2`（水平居中），
  `y(t) = h - (h+text_h)*(t-ts)/dur`——`t=ts` 时整块顶边贴画面下缘，
  `t=te` 时整块底边离开画面上缘，**速度随时长自适应**，时间轴数学不需要
  知道文本行数（`text_h` 是 ffmpeg 按整块文本实测的高度，含行距）。
- `text_align=C` 让块内每一行各自居中（片尾致谢体例）；表达式只含
  `h/text_w` 等变量与算术符号，无 `:` `,`，**不需要引号转义**；
  老 ffmpeg 缺该选项时探测后自动省略（`_drawtext_option_supported`）。
- `_apply_captions` 读 `_caption_style` 暂存键（随 `_captions` 一起从
  workflow 展开传递）：scroll 样式生成**一个**覆盖全片时长的 text overlay，
  sequential 样式走 V7.2 的逐片段绑定 / 均分铺轴，互不干扰。

## 计划形态

```json
{"workflow": {"name": "smart_create", "subtitle_style": "credits",
              "captions": ["出品：全家", "拍摄：妈妈", "主演：爸爸和二宝"],
              "budget_seconds": 20}}
```

`captions` 仍走三条来源（V7.4 起为可插拔提供器链）；schema 校验
`subtitle_style` 必须是预设表键之一，错误信息直接列出合法值菜单。

## 测试

bottom 样式不受影响、渲染命令含滚动 y 表达式与 text_align、
逐片段绑定路径回归。
