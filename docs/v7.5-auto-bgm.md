# V7.5 自动配乐（auto BGM）

> 2026-09-29。选曲思路参考 [FireRed-OpenStoryline](https://github.com/FireRedTeam/FireRed-OpenStoryline)
> 的 `select_bgm` 节点（Apache-2.0，引用见 THIRD-PARTY-NOTICES）。

## 动机

此前 BGM 只能靠用户显式上传音乐并在计划里写顶层 `audio` 块；一键成片
（one_click_reel / smart_create）对 INPUT/ 里的纯音频素材视而不见——
`_gather_ctx` 按扩展名把音频直接跳过，宏展开层根本看不到音乐。

## 内置曲库（V7.5.1）

`MUSIC/` 目录预置 **16 首 Mixkit 免费授权曲目**（约 88 MB）：欢快/童趣、
流行/轻快、原声吉他、氛围、企业宣传、嘻哈/Trap、爵士、电子/Techno 各 2 首，
命名 `mixkit-<曲名>-<id>.mp3`。来源与逐首溯源（下载直链/分类页/授权/实测
时长）见 [MUSIC/README.md](../MUSIC/README.md) 与 `MUSIC/meta.json`。

- **授权**：Mixkit Stock Music Free License——免费商用、无需署名，随成片
  渲染没有问题；但**禁止原始音频文件再分发**，故 `MUSIC/*` 不入 git
  （README/meta.json 除外），拉取仓库后按文档自行下载即可。
- **候选合并**：`_gather_ctx` 把 `MUSIC/` 与 `INPUT/` 的纯音频一起记入
  `ctx.music`，`_music_candidates` 排序**曲库优先**——回退第一候选、
  「唯一候选」都落在精选曲库上。
- **引用前缀**：`workflow.bgm` 与计划 `audio.source` 的合法前缀放宽为
  `INPUT/` 与 `MUSIC/`（`workflow.AUDIO_PREFIXES`，skills/plan_schema 同源）。

## FireRed 的做法（对照）

| 环节 | FireRed | 本项目 V7.5 |
| --- | --- | --- |
| 曲库 | 内置 99 首（`resource/bgms/`） | 内置 16 首 Mixkit 免费授权（`MUSIC/`，V7.5.1）+ 用户上传 INPUT/ 纯音频 |
| 曲目打标 | Qwen3-Omni 听音频打 scene/genre/mood 标签（`omni_bgm_label.py` → `meta.json`） | **Mixkit 人工标签抓取**（`scripts/label_music.py --provider tags`，零密钥）；omni 听感通道预留（`--provider omni`，需 DASHSCOPE_API_KEY）。本地 DSP 推 mood 实测无区分度，已放弃 |
| 召回 | all-MiniLM embedding + FAISS 语义召回 top-32 | 候选全量直接给 LLM（本地曲库量级小，不需要向量召回） |
| 终选 | LLM 候选 + 用户要求 → 选一首（失败降级候选第一条） | 同构：候选 + workflow.keyword → LLM 选一首（失败回退第一首） |
| 量化分析 | librosa：BPM/节拍/重拍 → 卡点剪辑 | 未做（卡点剪辑是独立特性，见路线图） |
| 混音 | 固定音量比（BGM 0.25）+ 循环/裁剪铺满 | 走既有 audio 块编译链：volume 0.3 + loop 铺满 + fade + 侧链闪避 |

## 实现

- **候选发现**（`plan_compiler._gather_ctx`）：不再按扩展名跳过音频，改为
  ffprobe 后**按流分类**——有音轨无视频轨的文件记入 `ctx.music`
  （`{rel: {duration}}`）。按流而非扩展名，非主流音频封装（.aac/.opus…）也能认出。
- **选曲与注入**（`workflow._attach_bgm`）：
  优先级 **计划自带 audio > workflow.bgm 指定曲目 > 自动选曲**。
  - 自动：1 首直接用；多首回喂 LLM 终选（复用 `_write_captions` 的
    「失败不卡出片」模式），选飞/不可用 → 回退排序第一的候选。
  - `workflow.bgm: false` 关闭；`"INPUT/x.mp3"` 指定曲目（不存在 →
    ValueError 回传 LLM，宁可报错也不静默换曲）。
  - 注入块：`{volume: 0.3, fade_in: 0.5, fade_out: 1.0, loop: true,
    ducking: 任一选中素材有音轨}`，混音全部复用既有编译器链路
    （`_bgm_input_args` / `_mix_bgm`），编译器零改动。
- **schema 校验**（`plan_schema._validate_workflow`）：`bgm` 必须是
  true/false 或 `"INPUT/..."` 字符串；speech_clean 不消费该参数（用了即报错）。
- **生效范围**：one_click_reel / smart_create（创作流）。speech_clean 是
  粗剪工具，挂音乐会改变其语义，不加。
- **report**：展开报告新增 `report.bgm = {source, selection, ducking,
  reason}`，`selection ∈ plan / explicit / llm / auto / disabled / none`。

## 行为矩阵

| INPUT/ 音乐 | 计划 audio 块 | workflow.bgm | 结果 |
| --- | --- | --- | --- |
| 有 | 有 | 任意 | 用户 audio 原样生效（selection=plan） |
| 有 | 无 | false | 不配乐（disabled） |
| 有 | 无 | "INPUT/x.mp3" / "MUSIC/x.mp3" | 用指定曲目（explicit；不存在则报错回传） |
| 有 | 无 | "轻松欢快" / "旅游"（无前缀文本） | 作为**氛围描述**交 LLM 选曲（llm；失败回退曲库第一首，style 记入报告） |
| 有 | 无 | 缺省/true | 自动选曲（1 首 auto；多首 llm 终选，失败回退第一首）。**V7.7 起注入 `original: "mute"` 纯 BGM**（volume=1.0，去掉素材原声） |
| 无 | 无 | 缺省 | 不配乐（none，报告说明原因） |

**氛围与关键词解耦（V7.5.2）**：`keyword` 是**镜头筛选**条件（拿去匹配
内容卡的场景/活动/标签），把「欢快」这类氛围偏好塞进去会把画面全筛没；
氛围偏好只放 `bgm` 自由文本，选曲 prompt 单独携带。曲库候选附带
`meta.json` 的 title/genre/tags（V7.5.3 人工标签）作为选曲语义信号。

**实测教训（打标通道选型）**：曾尝试用本地 DSP（RMS 能量 / 响度密度 /
谱通量起始率）推断 mood/energy——三个指标在本曲库上均无感知区分度
（最安静的 ambient 起始率最高、安静母带的欢快曲能量被判低），已放弃；
感知语义要么用发布方人工标注（tags），要么用音频理解大模型（omni）。
