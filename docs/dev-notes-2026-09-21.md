## 二、设计决策纪要（本次讨论结论）

### D1 · Skill 的两层观：注册表是原语层，用户动词是宏层

**问题**：skill 定义在滤镜层（hflip/eq/delogo…）是否太工程视角？该不该对应"一键成片、
给人脸打码、筛选素材"这类用户操作？

**结论**：两层都要，是上下层关系不是替代关系。

- **原语层（现有 skills.py）**：编译目标确定（`build` 出 vf 表达式 / `prepass` 出子命令），
  "一处定义、三处派生"（校验/编译/提示词）只有在这层成立。防幻觉 + 保编译正确，是地基。
- **宏层（将来，task skill）**：用户动词 → 计划声明 → **编译器确定性展开**。
  `auto_select: {"criteria": "has_face", "budget": 60}` 即其形态（P0-1 的原设计）。
- 分工原则不变：**LLM 出意图，展开的工程数学归编译器**。`face_mosaic` 是
  "用户动词恰好等于一个原语"的特例，不能拿特例当通则。
- **命名建议**：把"Skill"一词留给将来的用户动词宏层；现在的 skills.py 语义上改名
  capabilities/primitives（原语注册表），避免后来者混淆。

**为什么不能只有用户操作级**：用户操作无限、原语有限；有限原语的组合表达无限任务，
只登记高频动词则长尾请求真落空。"超出定义"当前的行为不是模型自由发挥，而是
显式失败 → 回传重试 → 相同错误短路/3 轮熔断（见 D4）。

### D2 · custom_filter 逃生舱：只允许逐帧像素变换

- **边界（2026-09-17 已澄清，本次重申）**：只允许逐帧像素变换（unsharp/gblur/vignette/
  curves/deshake…）；**禁一切改变时序的滤镜**（setpts 变速、倒放、抽帧、循环）——
  编译器按 `d = trim_end - trim_start` 推导时长并写死 `-t`，改时序会让时间轴数学失效
  （时长错、音画漂移、overlay 绝对时间错位）。变速必须走契约路径（T7b）。
- **四道闸**：dry-run 预检（T5，头道闸，✅ 已完成）/ 沙箱约束（禁写文件类、破坏性、
  超长耗时）/ 检视面板「未验证滤镜」标记 / 失败回传重试。
- **漏斗方向**：逃生舱是 Skill 的候补队列不是终点（T20：反复使用且验证稳定 → 升级注册）。
  没有第③层，逃生舱会退化成垃圾堆积场。
- 实现要点：它是一条普通 VF 类 Skill（`build()` 直接并 `args.vf` 进链），编译器无特殊逻辑；
  唯一增量是 precheck 阶段（本次已做）。

### D3 · speed 变速与 T4a 事件的准确复盘

- **ffmpeg 没有 `speed` 滤镜**（变速 = `setpts` 视频 + `atempo` 音频，单级 0.5~2.0 可链式）。
  skill 名是计划语言自己的命名，注册后即合法词——`face_mosaic` 同理（不对应任何 ffmpeg 滤镜）。
- **T4a 三层复盘**：① 感知/表达缺失——计划语言无法表达变速，模型被迫在 clip 对象上
  臆造字段；② 当时的漏洞是"自由 JSON + 部分校验"——校验只盯 effects 和少数字段，
  未知字段**静默忽略**，意图泄漏到未校验区域，系统报成功；③ 修复 = `_unknown_keys`
  铺满每层（封闭语言）+ retry 指令加"不支持的效果如实说明"。
  模型不是"学会绕过白名单"——是结构性泄漏，任何模型任何版本都会这样。
- **T7b 设计**：`Skill` 增加 `time_scale: 1/rate` 标记，`_derive()` 据此修正 `d_i` 与总时长 `D`，
  音频 atempo 链式。注册后"2 倍速"从"模型被迫编字段"变成合法单词。

### D4 · 防"杜撰"的机制观：不靠模型诚实，靠结构

四层结构（按"撒谎变难、诚实变易"排列）：

1. **合法出口**：`ask_user` 工具——承认做不到是计划语言里的合法动词，杜撰的动因下降；
2. **错误即教育**：回传报错自带白名单+收到的值+「不支持要如实说明」；2026-09-16 真实
   LLM 实验（`TMP/_diag_retry_real.py`）验证：模型收到回传后如实承认不支持并删字段；
3. **谎造不成假货**：模型陈述不产生任何产物——唯一物理动作是提交 JSON，被封闭语言包住；
   ffprobe 回验独立于模型。杜撰的最坏结局 = 多烧两轮重试 → 相同错误短路/3 轮上限 →
   T8 显式失败（绝不静默漏执行，反向剪映）；
4. **残余风险 = 语义幻觉**（参数全合法但意图错，如编时间戳冒充剪静音、用 eq 冒充变速）：
   靠 prompt_doc 写清语义边界（先例：eq 的 saturation=0=黑白 NOTE）+ T18 渲染级断言
   + 宏展开用真实信号（见 D5）。

### D5 · "剪静音为何现在做不到"与信号/宏分工

- **根因是感知缺失，不是执行缺失**：`probe_media` = `ffprobe -show_format/-show_streams`，
  只读容器头（时长/分辨率/编码/有无音轨），从不解码内容；静音区间这个事实在系统中不存在。
- **危险的细节**：计划语言语法上今天就能表达"剪多段"（手工枚举 clip+trim），且编造的
  时间戳**能通过全部现有校验**（类型对、范围对、渲染成功、时长自洽）——语义幻觉的
  实例。实际未发生靠的是 ask_user 的 prompt 约束，非结构保证。
- **分工准则**（回应"为什么不让模型自己调检测工具"）：

| 任务形态 | 例子 | 归属 | 理由 |
|---|---|---|---|
| 机械批处理 | 剪掉全部静音、全切点转场、全脸打码 | **编译器宏** | 规则统一量大无判断；模型手抄 247 个区间必漏（= 剪映式漏执行），宏展开是循环，构造性正确 |
| 带判断的选择 | "挑最有劲的三段""留半秒气口" | **模型 + 可见信号** | 需要品味取舍；模型读内容卡片手写显式 trim（今天已支持），将来配 auto_select/VLM |
| 长尾新滤镜 | 生僻锐化 | custom_filter 逃生舱 | 一次性，不值得注册 |

- **信号层模型可见**：T11 内容卡片挂在 probe_media 返回里（时刻Pro"上传即索引"的
  最小实现），检测工具加不加登记成本同量级——真正的分界是"誊抄归谁"。
- 宏可带参数（padding/min_silence）覆盖细粒度偏好；保底通道永远是模型手写显式 trim。
