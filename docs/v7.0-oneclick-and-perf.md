# V7.0 —— 一键成片 Workflow 宏 + 性能优化

> 2026-09-27。参考 [FireRed-OpenStoryline](https://github.com/FireRedTeam/FireRed-OpenStoryline)（Apache-2.0）
> 的 WORKFLOW SKILL 概念实现「一键成片」，并按其《性能瓶颈分析与优化建议》落实三项优化。
> 引用声明见 [THIRD-PARTY-NOTICES.md](./THIRD-PARTY-NOTICES.md)。

## 0. 链路结论：归一化前置的架构不需要改造

FireRed 的渲染链是「ffmpeg 流复制切片 → **moviepy 逐帧合成**」——其性能文档实测
50.5s 成片渲染 9.5 分钟（约 11 倍实时），瓶颈在编码前的 Python/numpy 逐帧合成
（自定义字幕层/程序生成转场遮罩是 moviepy 存在的理由）；文档自己给出的优化方向
就是「简单链路走纯 ffmpeg filter_complex 直出」。

**我们的链路恰好就是那个「正确答案」**：每 clip 一次归一化（裁剪+画布+效果，
一次重编码，产物规格统一）→ concat 流复制 / xfade filter_complex 渲染。
全程确定性命令、可 dry-run 预检、可回验。差异的本质是合成表达力：
moviepy 能做逐帧 numpy 特效，我们不做这类创意特效（Scope Guard），换来速度与
可验证性。**结论：不改架构，只在现有链路上做三项优化**（见 §2）。

## 1. 一键成片：workflow 宏

### 1.1 设计（对 FireRed WORKFLOW SKILL 的「编译器化」转译）

FireRed：markdown 定义主流程（加载→切镜头→理解→筛选→分组→时间线→渲染），
LLM 逐步调用 MCP 节点工具执行——流程正确性依赖模型遵守说明。
本仓库同一思想改为**计划级宏**：LLM 只挑工作流 + 填少量参数（budget/keyword/
transition），「粗筛→选材→编排」由编译器确定性展开，产物仍是普通计划，继续走
编译→dry-run→执行→回验→EDL 导出。零 MCP、零新服务，宏注册表与 skills.py 同构
（一处定义 → 校验/展开/提示词三处派生）。

### 1.2 两个内置工作流（`video_editing/workflow.py`）

- **`one_click_reel`**（用户说「帮我剪个视频」时的默认）：素材级粗筛丢废料
  （culling 规则）→ 画质选材（good/ok + 可选 keyword 的跨字段 OR 匹配 +
  静音比上限）→ 预算贪心（默认 30s，best_first）→ 默认 fade 0.3s 转场 → 出片
- **`speech_clean`**（口播净化）：有音轨且非全静音的素材逐条 cut_silence，
  无声/无音轨素材自动跳过并进报告（不报错）

计划形状：`{"workflow": {"name": "one_click_reel", "budget_seconds": 30,
"transition": 0.3, "keyword": "日落"}}`，与 clips/select/timeline/overlays 互斥，
output/audio（BGM）仍可用。select 新增 `text_any` 条件（场景/活动/氛围/标签
跨字段 OR——关键词语义不该要求同时命中多字段）。

### 1.3 实测（真实素材）

- 确定性路径（replan 提交宏）：粗筛拦下 2 个全静音 Pexels 素材 → 挑 2 镜头
  fade 拼接，17.27s 回验通过；
- 自然语言路径（「帮我把这些素材剪个视频，不用问我」）：模型 `ls` 一步后直接
  提交 workflow 宏（计划 0 手写 clips）→ 展开挑 3 镜头 → **35 秒端到端出片**，
  一轮零重试零反问。

## 2. 性能优化（对照 FireRed 性能文档逐条落）

| FireRed 文档建议 | 我们的对应 | 实现 |
|---|---|---|
| P0 串行 VLM → 并发 | `content_analysis.tag_shots` 批次并发（4 路，`VLM_CONCURRENCY` 可配），进度按完成数上报 | ThreadPoolExecutor + as_completed，结果按批号回填（乱序完成不乱序写入） |
| P1 重阶段前 preflight | 宏展开前 `_gather_ctx` 即校验：缺卡/全废料/无可用镜头立即结构化报错（可回传），不进渲染段 | workflow.expand 的 ValueError → CompileError |
| P2 渲染避免逐帧合成 | **架构本就如此**（§0）；补充：归一化产物**内容寻址缓存**——键 = 输入 stat + 裁剪 + 滤镜 + 目标规格，replan 未改片段/重试零重编码（实测同参数二次编译直接跳过归一化） | `_norm_cache_path` + 命中跳过；concat 清单随缓存路径更新 |
| （附加） | detect/normalize 命令 **2 路并行**，render 串行；取消语义保留（并行段收集已完成项再统一抛 Cancelled） | `execute()` 重写 |

实测收益：LLM 一键成片轮 35.2s 中归一化只跑了 1/3 片段（2 个命中缓存）。

## 4. 遗留与后续

- workflow 宏目前不接 BGM/字幕（等 T14 ASR 与曲库决策）；
- `speech_clean` 的静音阈值固定 -35dB/0.4s，计划级可配待需求出现再开；
- FireRed 的 generate_script/voiceover 属创作向，不在粗剪定位内（Scope Guard）。
