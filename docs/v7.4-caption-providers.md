# V7.4 文案可插拔提供器 + 文案驱动时长

> 2026-09-29。smart_create 的文案来源从「写死的三段 if」重构为**可插拔
> 提供器链**，并新增 **credits + 自带文案的「文案定长度、画面来填满」** 模式。

## ① CAPTION_PROVIDERS 可插拔链

```
plan（计划/用户自带文案——命中则生成模块完全不参与）
  → llm（选中镜头序列回喂模型现写，V7.2 的 _write_captions）
    → labels（无 LLM 时的标签拼接兜底）
```

- 先命中先赢：`fn(wf, picked, ctx) -> (captions | None, source | None)`，
  返回 `None` 让位下一个提供器；来源记录在 `report.captions_source`
  （plan / llm / labels）。
- **新来源 = 加一个 `(name, fn)` + usage 文案一句话**（例：模板库、
  远期 TTS 的逐行文案、按镜头情绪选风格），不动编排代码。
- 全部落空会显式报错（此前 labels 兜底永不落空，重构后链上任何一环
  想成为「可落空」的都必须自己声明兜底语义）。

## ② 文案驱动时长（credits 专属）

触发条件（三者同时成立）：`subtitle_style == "credits"` 且计划**自带
captions** 且**未显式给** `budget_seconds`——

```
target = 行数 × seconds_per_line（默认 1.2s/行，合法 0.5~5.0）
  → 选材用「软预算 = target + 最长候选」装填（允许略超）
  → _fit_duration_to_captions 把投影总时长精确收齐到 target
```

- **为什么先超再收**：装填是整数段的贪心，直接拿 target 当预算几乎必然
  欠额；软预算多给一个最长候选的余量，再由收尾阶段做线性减法。
- **收尾数学**：末段 `trim_end` 回收是线性减法（转场重叠数不变，总时长 D
  随 trim 量 1:1 减少）；末段收短不低于 `MIN_SHOT_DURATION`(1.5s)，
  违反时在「收到下限」与「整段丢弃」之间取投影时长更贴近 target 者。
- **素材不足时诚实接受欠额**（镜头太长装不满 target），实际值记入
  `report.duration_source`（`captions` / `budget` / `default`）。
- 显式给了 `budget_seconds` 则**预算优先**——提示词要求模型在
  「文案驱动」与「预算驱动」之间替用户做明确选择，不悄悄混用。

与 V7.3 的关系：credits 的滚动速度随时长自适应，若时长由预算决定、
文案行数又多，滚动会快到读不完——文案驱动时长正是 credits 体例的
自然配套（「致谢名单决定片长」，电影片尾同理）。
