# V7.7 音频控制（原声去留 + 逐段控声）

> 2026-10-01。需求来源：加了 BGM 之后成片里还混着素材杂乱的原声；用户
> 想要「哪一段用什么声音」的控制力。

## ① 顶层 `audio.original` —— BGM 下原声的去留

```json
"audio": {"source": "MUSIC/mixkit-forest-walk-607.mp3",
          "volume": 1.0, "original": "mute"}
```

- **缺省 `"mute"`（V7.7.1 翻转）**：**BGM 即全部声音**——只要加了 BGM，
  素材原声就删掉（模型手写的 audio 块不写 original 字段同样生效），
  混音层不再 amix 原声轨，BGM 链（裁时长→音量→fade）直接作为成片音轨，
  `volume` 语义为成片音量（配 mute 用 ~1.0）。
- `"keep"`：BGM 与素材原声 amix（配 `volume: 0.2~0.4` 垫在人声下）。
  **保留原声只有这一条显式路**——没有任何隐含保留的旁路（曾有
  「ducking 隐含 keep」规则：模型顺手写 ducking 就把原声留下了，已删）。
- `ducking` 的合法性：仅当显式 `original: "keep"` 时允许；缺省/`mute`
  下写 ducking 直接判错回传（闪避需要原声当 sidechain 触发信号）。
- 与逐段换声冲突预检（`mute_vs_clip_audio`，用户可决）：换声属于原声轨，
  会被全局静音吞掉；二选一。
- 判定逻辑单一实现：`skills.original_mode`（schema 预检 / 编译器混音同源）。

**自动配乐策略为纯 BGM**：`_attach_bgm` 注入
`{original: "mute", volume: 1.0}`——一键成片的素材原声多为杂乱环境音/
碎语，直接被音乐替代。

## ② clip 级 `audio` —— 哪一段用什么声音

每个 clip 可携带自己的小 `audio` 块，决定**该片段在归一化产物里携带的声音**：

```json
{"id": "c2", "source": "INPUT/b.mp4", "kind": "video",
 "audio": {"mute": true}}
{"id": "c3", "source": "INPUT/c.mp4", "kind": "video",
 "audio": {"source": "INPUT/narration.m4a", "volume": 1.0, "loop": true,
           "fade_in": 0.5, "fade_out": 0.5}}
```

- `{"mute": true}`：本段静音（BGM-only 段）。
- `{"source": "INPUT/.. | MUSIC/.."}`：**换声**——本段音频替换为指定文件，
  `loop`（缺省 true）循环铺满或裁到片段时长；图片素材同样成立（照片配乐）。
- `volume` / `fade_in` / `fade_out`：作用于本段实际携带的声音
  （原声或替换声）；`mute` 与 `source/volume/fade_*` 互斥。
- 与 `cut_silence` / `cut_black` 互斥：废段检测依据原声/画面，声音被
  覆盖后检测结果不再可信。

典型组合：口播段保留原声 + b-roll 段 `{"mute": true}` + BGM
`original: "keep"` + `ducking: true`。

## 实现

- **归一化阶段落地**（`_normalize_commands`）：静音 → norm 补
  `anullsrc` 音轨；换声 → 替换音频作为额外输入（`-stream_loop` 可选）
  被 `-map` 选中，`volume/afade/apad` 进 `-af`，`-t 片段时长` 收口。
  下游 concat / xfade / BGM 混音链路**零特判**——它们只认 norm 产物。
- **缓存键**：`_norm_cache_path` 新增 `audio_key`（clip.audio 的 JSON），
  回改声音必定重编码，不命中旧缓存。
- **混音层**（`_mix_bgm`）：`original == "mute"` 时跳过 amix/ducking，
  返回 `[bg]` 作为成片音轨。
- **校验**：`skills.validate_audio`（original 字段 + mute/ducking 冲突）、
  `plan_schema._validate_clip_audio`（clip.audio 全量校验）、
  `check_material_fit`（`mute_vs_clip_audio` 预检，
  `_MISMATCH_OPTIONS` 给修复选项回传）。
