# V7.8 修复：dry-run 预检在 xfade 任务上挂起

> 2026-10-01。V5 落地的 dry-run 语法预检（T5）在「多片段全接缝转场 +
> 逐片段字幕」的真实任务上 60 秒超时被杀，且报错信息丢掉了真因。
> 本轮修两处：预检命令的 xfade offset 压平 + 报错正文的原因优先级。

## 现场与根因

- **现场**：5 片段全部接缝转场 + 逐片段字幕的任务，预检报「dry-run 语法
  预检失败」，ffmpeg stderr 只有 libx264 启动日志，末行
  `non-strictly-monotonic PTS`，命令挂满 `PRECHECK_TIMEOUT`(60s) 被杀。
- **根因（ffmpeg 6.1 实测）**：dry-run 用 **0.5s 合成素材**顶替真实输入，
  而 xfade 的 `offset` 是**真实时间轴起点**（5 片段链式转场可达几十秒）——
  第一个输入早早 EOF，xfade 等`offset` 时刻的帧**不吃 EOF 直接死锁**。
- **报错为什么失真**：`precheck` 的报错正文优先抓 stderr「实质行」，
  把运行层真正的原因（`error` 字段里的「命令超时」）让位给了无害日志。

## 修复

1. **`_dry_argv_render` 把 filter_complex 里 xfade 的 offset 一律压成 0**
   （正则替换）——语法预检只需要验证滤镜链能被 ffmpeg 解析，不需要语义
   保真；实测 offset=0 时即使 duration 超过合成素材时长也不会挂。
   同理 **acrossfade 的 `d` 压到 `PRECHECK_ACROSSFADE_D`(0.05)**：
   链式 acrossfade 每级把音频缩短 d，0.5s 预检素材几级之后就比 d 还短，
   同样死锁。
2. **报错正文让运行层原因优先**：超时/启动失败（`error` 字段）排在
   stderr 尾部日志之前，两者都保留——「命令超时（60s）」在前，
   `non-strictly-monotonic PTS` 等尾部日志附后，定位不再失真。

真实渲染不受影响：压平只发生在 `_dry_argv_render` 生成的预检 argv 里，
渲染命令的 offset/d 原样。

## 测试

`tests/test_v78_precheck_offset.py`（离线 + 真实 ffmpeg 冒烟）：

- `test_dry_argv_clamps_xfade_offsets`：含大 offset 的转场链，预检 argv 的
  offset 全部 ≤ `PRECHECK_DUR`、acrossfade d ≤ `PRECHECK_ACROSSFADE_D`，
  合成引用/`-f null -` 收尾不变；
- `test_dryrun_no_hang_with_real_ffmpeg`：同一计划真实跑 precheck，
  30 秒内返回且 ok（此前必然 60s 超时）；
- `test_timeout_reason_surfaces_over_stderr`：人为让命令超时，「命令超时」
  出现在报错正文且 stderr 尾部不丢。
