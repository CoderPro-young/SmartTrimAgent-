## 一、修复清单

### R1 · prepass 参数进归一化缓存键（v7.7 已知边界的正式关闭）

- **原问题**：`face_mosaic` 等 PREPASS 技能产物为固定名
  `TMP/{cid}_<skill>.mp4`，归一化缓存键（含 src 路径 + 原素材 stat）不含
  prepass args——改打码参数后归一化直接命中旧缓存，新效果不出片。
- **修复**（plan_compiler.py）：产物名改为
  `TMP/{cid}_<skill>_<指纹>.mp4`，指纹 = sha1(args 规范 JSON + 输入 stat)
  前 8 位。参数变 → 路径变 → 归一化键自动失效；输入 stat 进键顺带覆盖
  「原素材同名替换」的洞。产物已存在且非空则跳过 prepass 重跑
  （prepass 是全片渲染，replan 未改参数时秒级复用）。
- **测试**：tests/test_preview_quality.py t06/t07（参数敏感性、幂等、
  归一化键联动失效、存在即跳过、空文件不跳过）。
- v7.7-preview-quality.md 的「已知边界」条目已标注关闭。

### R2 · 「要方案先别动手」的结构保证（2026-10-15 事故关闭）

- **原问题**：用户消息「先别急着剪，给我几个替代方案」——classify 按
  祈使标记（「给我」∈ `_IMPERATIVE`）判 task 直接进规划 agent；是否
  ask_user 全靠模型自觉（ask_user 是合法出口而非结构保证，Flash 瞬时
  误判即开剪，10-15 用户实际遇到）。
- **修复**（三层，D4「不靠模型诚实，靠结构」）：
  1. intent.py 新增 `is_proposal_request()`：方案词（替代方案/备选/选项…）
     与制动词（先别/别急/先不剪/我想想…）命中即 True；「用方案C」类
     已选定回复（执行授权）不拦。classify 的 question 分支同步接入：
     「有没有别的方案？先别动手」不再判 status_question 答非所问地
     汇报现状，而是放行 task + `basis=rule-proposal`。
  2. server.py：命中即给 agent 的任务文本追加 host 指令——
     「本轮禁止 submit_plan，ask_user 给出 2~4 个方案」。只影响本轮
     发送，不污染 session["task"]。
  3. video_agent.py ask_user 段新增普适规则：用户要选项/替代方案时
     必须 ask_user 出 2~4 个方案，「用户下一轮的选定才是执行授权」。
- **测试**：tests/test_v9_understanding.py t15（正反例 + classify 联动）。

### R3 · edit_plan 的 clip id 誊抄自救（实测新发现）

- **实测**（simtest2 修订轮）：agent 把 `c9` 誊成大写 `C9`，5 条 ops
  全报「片段不存在」，浪费一轮重试。**根因**：OPS_DOC 示例全用大写
  `C1`，而真实计划的 id 是小写 `c1`——提示词在教错误风格。
- **修复**（plan_ops.py）：① OPS_DOC 示例 id 改小写 + 头部加「id 必须
  逐字引用，大小写敏感」；② `_find_clip` 报错附实际可用 id 清单
  （对齐 plan_schema「素材不存在时列 INPUT/ 实际文件」的自救模式）。

**顺带的实测观察**（不修，留证据）：
- `_narration` 首次提交曾臆造 `group_id_note` 字段 + `units` 形状错——
  校验拦截 + 一轮重试修复。提示词无缺陷（形状已写明、units 可省略也
  写了），属模型对嵌套 schema 的一次性失误率，重试闭环兜住。这是
  T6（validate_plan 试算工具）「等重试轮数成为实测痛点再开」的实测
  证据：当前一轮内自愈，暂无感。
- 探测阶段 agent 会 probe 全部素材（含任务未提及的）——少量冗余调用，
  无害。
