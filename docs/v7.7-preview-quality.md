# V7.7 预览档渲染（preview quality）

> 2026-09-30。目标：把「自然语言反复调整」环路的等待从分钟级压到秒级，
> 贵的完整编码只在用户满意后的「导出成品」发生一次。

## 动机

V5 起的调整环路是：自然语言 → LLM 改计划 → 编译 → 渲染 → 用户看片 → 再提修改。
其中归一化层早有内容寻址缓存（V7），**未改动的片段不重编码**；但只要计划带
转场 / 叠加 / BGM，最后合成一遍（xfade 链 + drawtext + 音频混音）仍要对全片
重编码——这是全时间轴效果的本性，长片上每次调整都要等几十秒到几分钟。

考虑过两条路：

- **按段打补丁**（对上一版成片剪切替换修改段）：否决。BGM/字幕/侧链闪避是
  全时间轴效果，换中间一段整条音轨要重混；xfade 让相邻片段重叠，改时长则
  下游全部平移；`-c copy` 拼接有参数一致性与代损问题，与「能直接发的成品」
  定位冲突。它能省的（未改片段不重编）缓存已经省了。
- **浏览器实时预览引擎**（剪映网页版架构）：效果词汇表要维护第二套浏览器
  实现，delogo / face_mosaic / 侧链闪避只能近似，长期税高。留作后续路线，
  本版不碰。

最终采用**同一条滤镜链、两档编码质量**：预览档换速度，导出档保质量，
预览所见即导出所得（零保真风险）。

## 设计

- **档位只作用于编译产物与命令参数，plan 永远不被污染**：编辑计划保持
  原始分辨率与正式文件名。预览档在编译期改写 `math` 的画布规格
  （`_apply_quality`：短边压到 540p、偶数对齐、记录 `src_width/height`、
  打 `preview` 标），导出档原样。
- **编码参数分档**（`_norm_vcodec` / `_render_vcodec`）：
  | 档位 | 归一化 | 合成渲染 | 产物 |
  | --- | --- | --- | --- |
  | final（缺省） | veryfast · crf 18 | crf 20（维持原行为） | `OUTPUT/<name>` |
  | preview | ultrafast · crf 23 | ultrafast · crf 24 | `OUTPUT/<name>_preview` |
- **缓存两档天然分开**：归一化缓存键含 `WxH`，预览/成品各自成套互不覆盖；
  键里再追加 `preview` 标记兜底（final 的键保持与 V7 逐字节一致，不炸旧缓存）。
- **字幕观感一致**：drawtext 字号/描边/行距按画布缩放比缩小
  （`_font_ratio` = 预览高/计划高），预览里的字幕构图与成品成比例。
- **已小于 540p 短边的画布不放大**，只打 preview 标走快编。

## 实现

- `plan_compiler`：`compile_plan(plan, root, quality="final")` 新参；
  `output_filename(plan, math)` 统一预览文件名推导，渲染命令与
  `verify()`（ffprobe 回验）都走它——预览产物回验的是 `*_preview` 文件。
- `video_agent`：`plan_with_retry(..., quality=...)` 透传到 `compile_plan`。
- `web/server.py`：`/api/run` 与 `/api/replan` 的 payload 均接受
  `preview: bool`；档位记入会话（`session["preview"]`，多轮对话沿用最后一次
  档位）；`done` 事件新增 `preview` 字段；**预览轮跳过 EDL/CSV 时间线导出**
  （那是正式交付物）。
- 前端（零构建 ES modules）：
  - 输入区新增 **「快速预览」** 开关（勾选后 run/replan 请求带 `preview: true`）；
  - 成品标签：预览轮亮 **「预览版 · 快速渲染」** 徽标 + **「导出成品（完整编码）」**
    按钮（= 对当前计划发 `preview: false` 的 replan），审阅报告结尾按档位
    切换提示语；下载链接文案区分「预览视频 / 原视频」。
- 档位不入计划 JSON：LLM 不感知档位，重开任务回到 final 缺省。

## 使用流程

```
勾选「快速预览」→ 提需求/对话修改/参数卡回改 → 秒级出 *_preview.mp4
   → 满意后点「导出成品（完整编码）」→ 原分辨率完整编码出正式成片
```

首次预览会把全部片段按 540p 归一化一遍（低分辨率 + ultrafast，本身就快），
之后只重编被改的片段；首次导出同理按原分辨率归一化一遍后全程缓存复用。

## 测试

- `tests/test_preview_quality.py`（5 项，离线编译级）：画布缩放且 plan 不被
  污染、编码参数分档、drawtext 字号/描边/行距缩放、xfade 转场路径、
  缓存键分档与 `output_filename` 单元断言。
- 全量回归：既有 10 个测试文件 134 项全部通过（无回归）。
- 真实渲染冒烟（ffmpeg 6.1.1，xfade + drawtext 合成素材）：预览档 1.5s 出
  960x540、成品档 2.8s 出 1280x720、回验均通过；重跑预览归一化缓存全命中
  （0 条编码命令）。长素材下预览/成品耗时差按分辨率与 preset 放大。

## 已知边界

- 预览档分辨率与成品不同，逐帧级细节（噪点、压缩伪影）不代表成品，
  构图 / 节奏 / 字幕 / 转场时机完全一致。
- `face_mosaic` 等 prepass 技能的 args 尚未进归一化缓存键
  （产物固定名 `TMP/{cid}_<skill>.mp4`）——改打码参数可能命中旧缓存，
  待后续把 prepass 参数哈希进产物文件名。
- 浏览器实时预览引擎（零编码预览、逐帧拖拽）仍在路线图，本版的时间线 UI
  与档位语义为其预留了复用点。
